# PADMÉ — data release

Companion data for the code release. It sits at `dataset/` in the repository root, which is
where the tools look by default. From the repository root, with no API keys and no model calls:

```bash
python tools/run_evaluators.py --dataset dataset/benchmark/eval_dataset.json \
                              --out-dir dataset/evaluations --report-only
python tools/report.py
python tools/report_human.py
```

If you host the data separately, point `--data` at wherever you unpacked it.

## Contents

### `benchmark/` — the synthesized dataset

| file | | |
|---|---|---|
| `eval_dataset.json` | 38 MB | the 1,000 pairs, **blind**: `id`, criterion name and description, the rendered shared context, and both conversations |
| `eval_answers.json` | 2.0 MB | the labels, joined on `id`: `correct_response`, slot-ordered `levels`, both steering instructions, `group_id`, `agent` |
| `judge_votes.json` | 2.1 MB | both filter judges on all 1,673 draws: side chosen, A/B order, retry count |
| `pair_index.json` | 944 KB | per-cell draw record: which draws were made, which kept, which re-drawn |

Blind and answers are separate files because `levels` is slot-ordered and the steering
instructions name their own direction, so a single record carrying both hands over the answer.
They intersect on `id` and nothing else.

### `evaluations/` — the evaluator sweep

25 models x 1,000 pairs x 3 runs. Per model: `{model}.results.json` (per-pair scores),
`{model}.metrics.json`, `{model}.usage.json`. Plus `summary.json` and a pooled `usage.json`.

`results.json` files are score-only: the prompt and both conversations were removed because they
duplicate `eval_dataset.json` verbatim and rejoin on `id`. Evaluator reasoning text was never
retained.

### `human_study/` — the 150-pair validation subset

| file | | |
|---|---|---|
| `pairs.json` | 5.5 MB | the 150 pairs as annotators saw them, blind |
| `answer_key.json` | 33 KB | per pair: the steering label, and `filter_outcome` (`kept`, `judge1_reject`, `judge2_reject`) |
| `sampling.json` | | how the 150 were drawn: seed, strata, pool |
| `panel_1/`, `panel_2/` | | three annotators each, `annotator_N.json`: `id`, `criterion_name`, `judge_preference` (1 or 2), `confidence` (0 / 50 / 100 = guess / leaning / certain) |

The 150 were drawn from **all** draws, not only the kept ones, which is why `pairs.json` is a
separate file rather than a subset of `benchmark/`: 46 of the 150 are pairs the filter rejected
and so do not appear in the 1,000. `filter_outcome` defines the nested arms — all 150, the 114
judge1 kept, the 104 both judges kept.

**Annotator identity is not in this release.** It was never in the records, which carry no name,
identifier or contact field. It was in the source filenames, and those are replaced by
`annotator_N` in an order that is deliberately not the original one, so the numbering cannot be
lined up against any list of people. Numbering is scoped to a panel; nothing in the analysis
needs more, because every statistic is either per-panel or over unordered pairs of raters.
Annotators were volunteers, compensated, told the task was voluntary and interruptible, and no
personal data was collected.

## Provenance and terms

Conversations were generated by `gpt-oss-120b`, `gpt-oss-20b` and `nemotron-lightning-3.5`
acting inside tau3-bench environments. Model outputs are subject to the terms of service of
whichever provider produced them; the task, policy and persona material is tau2-bench's and
remains under its license. Customer names, addresses, emails and phone numbers in these
conversations are tau2-bench synthetic fixture data, or were invented by a model in-conversation
for those fixture personas. They do not refer to real people.

See the code release's `NOTICE` for the full attribution chain.
